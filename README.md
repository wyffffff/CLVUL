# Code-Text Contrastive Learning for Software Defect Detection

This repository implements a code defect detection framework based on **code-text contrastive learning**. The model uses a UniXcoder/Roberta-style encoder to extract semantic representations from source code and aligns them with trainable label-text embeddings. The framework is designed for binary software defect detection, where each code sample is classified as either defective or non-defective.

## Overview

The core idea of this project is to represent both source code and defect labels in a shared semantic embedding space. Instead of using a conventional classification head, the model compares the embedding of each code sample with the embeddings of label descriptions.

The default label descriptions are:

```python
LABEL_DESCRIPTIONS = {
    0: "This code does not contain defects.",
    1: "This code contains defects."
}
```

During training, the model learns to pull code representations closer to their corresponding label embeddings and push them away from incorrect label embeddings.

## Main Features

- Uses `unixcoder-base-nine` as the default pretrained encoder.
- Supports binary software defect detection.
- Encodes source code using a pretrained Transformer model.
- Initializes label embeddings from natural language label descriptions.
- Uses a label contrastive learning objective based on code-label similarity.
- Supports GPU acceleration with PyTorch.
- Automatically splits the dataset into training, validation, and test sets.
- Saves the best model according to validation accuracy.
- Reports Accuracy, Precision, Recall, F1-score, and a detailed classification report.

## Dataset Format

The default dataset file is:

```text
labelcode.csv
```

The CSV file should contain at least two columns:

| Column | Description |
|---|---|
| Column 1 | Label, where `0` means non-defective code and `1` means defective code |
| Column 2 | Source code text |

Example:

```csv
label,code
0,"int add(int a, int b) { return a + b; }"
1,"void copy(char *src) { char buf[8]; strcpy(buf, src); }"
```

In the current implementation, the dataset class reads labels from the first column and source code from the second column.

## Model Architecture

The model consists of two main components:

### 1. Code Encoder

The code encoder is initialized from a pretrained Roberta-style model:

```python
self.code_encoder = RobertaModel.from_pretrained(model_name)
```

For each code sample, the model uses the hidden state of the first token as the global code representation:

```python
code_embeddings = code_outputs.last_hidden_state[:, 0, :]
```

The code embeddings are normalized before similarity computation.

### 2. Label Text Embeddings

The model also initializes label embeddings from natural language label descriptions. These embeddings are generated by a text encoder and then converted into trainable parameters:

```python
self.label_embeddings = nn.Parameter(label_embeddings)
```

This allows the model to refine label representations during training.

## Training Objective

The training loss is implemented as `LabelContrastiveLoss`.

Given code embeddings and label embeddings, the model computes a similarity matrix:

```python
logits = torch.matmul(code_embeddings, label_embeddings.t()) / temperature
```

Then cross-entropy loss is applied to encourage each code sample to be closest to its correct label embedding.

## Data Splitting

The dataset is automatically split into:

| Split | Ratio |
|---|---|
| Training set | 80% |
| Validation set | 10% |
| Test set | 10% |

The split is performed with a fixed random seed to improve reproducibility.

## How to Run

Place your dataset file in the project directory and make sure it is named:

```text
labelcode.csv
```

Then run:

```bash
python train.py
```

During training, the script will:

1. Load the tokenizer and dataset.
2. Split the dataset into training, validation, and test sets.
3. Initialize the code-text contrastive learning model.
4. Train the model for the specified number of epochs.
5. Save the best model based on validation accuracy.
6. Evaluate the best model on the test set.

The code uses a fixed random seed:

```python
set_seed(42)
```

This helps make dataset splitting and model training more reproducible. However, complete reproducibility may still depend on hardware, CUDA version, PyTorch version, and other system-level factors.

## Notes

- The default maximum sequence length is set to `1024`, which may require sufficient GPU memory.
- If CUDA memory is limited, consider reducing `BATCH_SIZE` or `MAX_LENGTH`.
- The default model name is `unixcoder-base-nine`. Make sure the model is available locally or can be downloaded from the model hub.
- The current implementation is designed for binary classification, but it can be extended to multi-class vulnerability or CWE classification by adding more label descriptions.

## Possible Extensions

This framework can be extended in several directions:

- Few-shot or zero-shot defect classification using textual label descriptions.

- Integration with AST, CFG, or data-flow representations.
- Replacing the encoder with CodeBERT, CodeT5, UniXcoder, or other code pretrained models.
- Adding a stronger contrastive loss or supervised contrastive learning objective.
